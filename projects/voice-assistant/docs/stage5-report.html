二、核心缺陷：ASR 模型选型错误

现象 无论输入是正弦波、合成语音还是静音，ASR 都输出重复乱码，例如：
春侣熏熏熏柤柤剽瀍戒犀犀啶峰踵诰诰澌诰翎宇宇峰去去anyanyanyanycercer…

根因分析

此前下载的模型是 iic/speech_paraformer-large_asr_nat-zh-cn-16k-common-vocab8404-online-onnx， 这是流式（online）模型，输入需要按块（chunk）组织并携带上下文状态； 而代码使用的 funasr_onnx.Paraformer 是离线整段推理类， 两者输入结构不兼容，解码器拿到的特征始终错位，因此输出必然是乱码。

二次踩坑：路径过滤失效

改用离线模型后，程序仍优先加载 online 版本。原因是过滤逻辑写成了 "online" not in Path(p).name，而快照目录名是 master 与 v2.0.4，不含 “online”，过滤条件从未生效。改为对完整路径判断后才正确选中离线模型。 

# 修复前：只看最后一级目录名
offline = [p for p in candidates if "online" not in Path(p).name.lower()]

# 修复后：对完整路径判断
offline = [p for p in candidates if "online" not in p.lower()]

四、工程健壮性改进

1. 噪声输入兜底

静音或环境噪声会被 ASR 幻觉成高重复文本（如连续的“峰峰峰”）， 直接喂给 LLM 会触发超长生成。新增 clean_asr_text()： 单字符占比超过 50% 且长度 ≥ 8 时判定为无效，直接提示“没有识别到有效语音”。

2. 生成长度上限

LLM 请求增加 options.num_predict = 512， 限制单次回答长度，避免异常输入在 CPU 上生成两分钟以上导致请求超时。

3. 模型路径统一

find_asr_model_dir() 收敛到 voice_assistant.py，CLI 与 API 共用同一套查找逻辑， 消除两处重复实现带来的不一致。

4. 上传与会话安全

上传文件仅接受 .wav，临时文件在 finally 与 BackgroundTask 中删除； 同步阻塞的 ASR 与 LLM 调用统一放入线程池，避免阻塞事件循环。

六、遗留问题与下一步

  1. 真人语音实测：当前用合成音完成自测，合成音与真人声分布不同，需要对着麦克风实测识别率，这是上线前的关键验证。
  2. 流式识别：现有链路必须等整段录音结束才出结果。若要用已下载的 online 模型做边说边识别，需引入 paraformer_online_bin 的流式调用方式。
  3. 音频格式扩展：目前只接受 16 kHz wav。网页端如果需要直接录音，需引入 MediaRecorder（webm）并在服务端转码。
  4. 访问范围：服务无鉴权，仅适合可信内网。对外暴露需要加反向代理与身份校验。
  5. 资源占用：离线 ASR 模型 227 MB，常驻内存后与 Ollama 同时运行，对内存较紧张的机器需要评估。
