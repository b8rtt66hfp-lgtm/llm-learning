# 微调原理（SFT / LoRA / QLoRA / RLHF）

> **写给你**：这份笔记回答三个问题——为什么要微调、全参微调为什么跑不动、LoRA 为什么能省一个数量级的显存。目标是面试时能把每个设计决策的"为什么"讲出来，而不是只会调参。

---

## 一、先分清三件事：预训练 / 微调 / RAG

| 手段 | 干什么 | 类比 |
|---|---|---|
| 预训练 Pretrain | 用万亿级 token 学"预测下一个词"，获得语言能力和世界知识 | 教一个文盲认字 |
| 微调 SFT | 用几百到几万条"输入→输出"配对，把模型行为掰到你要的方向 | 教大学生按公司规范写报告 |
| RAG 检索增强 | 外挂知识库，回答时先查资料再作答 | 给这个人配一个随时可查的资料库 |

**关键认知：SFT 主要改"怎么说"，不负责"知道什么"。**

想让模型掌握 1000 页机械设计手册，应该上 RAG；想让模型说话像你们的资深工程师、输出固定格式的工艺卡，才上微调。

> 这条对预期管理很重要：用 25 条数据微调 Qwen2.5-1.5B，微调前后答案"差不多"是正常现象。小数据 + 小模型只能学到语气、格式、术语习惯，学不到成体系的新知识。

## 二、SFT：监督微调

### 2.1 数据长什么样

```python
{'messages': [
    {'role': 'user', 'content': '键连接的作用是什么？'},
    {'role': 'assistant', 'content': '键连接用于实现轴与轮毂之间的周向固定，并传递扭矩……'},
]}
```

把整段对话用 chat template 拼成一个 token 序列，算交叉熵损失。

### 2.2 为什么必须屏蔽 prompt 的 loss

模型的训练目标是"给定前文，预测下一个 token"。但 SFT 场景下，**提问是我们给的条件，不是要让模型学会生成的内容**。

所以要把提问部分对应的 labels 全部设成 `-100`：

```python
prompt_ids = tok.apply_chat_template(messages[:-1], tokenize=True, add_generation_prompt=True)
full_ids   = tok.apply_chat_template(messages, tokenize=True, add_generation_prompt=False)

labels = [-100] * len(prompt_ids) + full_ids[len(prompt_ids):]
```

`-100` 是 PyTorch `CrossEntropyLoss` 的默认 `ignore_index`，这些位置的梯度恒为 0。

不屏蔽会怎样：模型把"怎么提问"也当学习目标，浪费可训练容量，还容易学会复述问题。

### 2.3 面试标准答法

> 问：SFT 为什么屏蔽 prompt 部分的 loss？
> 答：SFT 的目标是建模"给定输入的条件生成分布"，输入是条件不是目标。屏蔽后梯度只来自回答部分，训练更聚焦，也避免模型学会复述提问。

## 三、全参微调为什么在消费级显卡上跑不动

以 Qwen2.5-1.5B（15 亿参数）为例，fp16 精度：

| 项目 | 计算方式 | 显存 |
|---|---|---|
| 模型权重 | 1.5B × 2 字节 | 3 GB |
| 梯度 | 与权重同尺寸 | 3 GB |
| AdamW 优化器状态 | 1.5B × 4 字节 × 2（m 和 v） | 12 GB |
| 激活值（中间结果） | 与 batch、序列长度相关 | 2~6 GB |
| **合计** | | **≈ 20 GB+** |

T4 只有 16GB，装不下。7B 模型同理需要 80GB 级别，得上 A100。

**一个反直觉的点：优化器状态比模型本身还大。**

AdamW 给每个参数额外保存两个 fp32 滑动统计量，所以"参数量 × 2 字节"只是权重，完整训练显存大约是权重的 6~7 倍。很多人估算显存时栽在这里。

## 四、LoRA：只学"修正量"

### 4.1 核心假设

微调带来的权重改变量 ΔW 是**低秩**的，不需要存满整个 d×k 矩阵。

于是冻结原权重 W，旁挂两个小矩阵 B、A 去拟合这个增量：

```
W_new = W_frozen + (alpha / r) * (B @ A)

W : d × k   （例如 1536 × 1536 = 236 万参数，冻结不动）
A : r × k   （r=8 时 8 × 1536 ≈ 1.2 万）
B : d × r   （1536 × 8 ≈ 1.2 万）

原来要更新 236 万个数 → 现在只更新 2.4 万，省约 100 倍
```

### 4.2 三个必须知道的细节

**① B 初始化为 0**

训练开始时 `B @ A = 0`，`W_new` 完全等于原模型。等于从原模型"热启动"，第一步不会破坏原有能力。这是 LoRA 稳定性的来源。

**② alpha / r 是缩放系数**

实际增量是 `(alpha/r) × B@A`。alpha 固定时改 r，等价于改有效学习率量级。

常用配置：`r=8~16`，`alpha=2r`。数据越少、任务越简单，r 应越小（防过拟合）。

**③ 挂在哪些层**

| 挂载范围 | 效果 |
|---|---|
| 只挂 `q_proj, v_proj` | 原论文做法，省参数，效果一般 |
| 挂全部注意力投影 `q/k/v/o` | 较好 |
| 再加 FFN `gate/up/down` | 当前主流，效果最好，参数量仍极小 |

### 4.3 LoRA 的显存账（同 1.5B 模型）

| 项目 | 显存 |
|---|---|
| 冻结的模型权重（fp16） | 3 GB |
| LoRA 参数 + 梯度 + 优化器（约 9.2M 参数） | ≈ 0.11 GB |
| 激活值 | 1~2 GB |
| **合计** | **≈ 5 GB** |

可训练参数占比：约 9.2M / 1.5B ≈ **0.6%**。T4 轻松装下。

### 4.4 推理时可以合并

```python
merged = model.merge_and_unload()
```

把 `B@A` 直接加进 W，得到一个普通模型，**推理零额外开销**。这是 LoRA 相比 Adapter 类方法最大的工程优势——上线不用多算一层，也不改推理框架。

### 4.5 LoRA 学不到什么

- 学不到成体系的新知识（那是继续预训练或 RAG 的事）
- 数据太少时只能学到语气和格式
- 对小模型的"能力提升"有限，主要是"行为对齐"

## 五、QLoRA：连基座都压成 4bit

LoRA 省掉的是梯度和优化器状态，但**冻结的基座仍然是 fp16**。7B 模型 fp16 就是 14GB，T4 还是装不下。

QLoRA 做两件事：

1. 把冻结的基座量化成 **4bit NF4**（分位数量化，比普通 int4 更贴合正态分布）
2. LoRA 旁路仍然用 bf16 训练，前向时临时反量化

| 模型 | fp16 基座 | 4bit 基座 |
|---|---|---|
| 1.5B | 3 GB | ≈ 0.8 GB |
| 7B | 14 GB | ≈ 3.5 GB |
| 13B | 26 GB | ≈ 6.5 GB |

代价：反量化带来额外计算（慢 20%~40%），量化有精度损失。

**结论：显存不够就上 QLoRA，这是个人开发者微调 7B/13B 的标准解法。**

## 六、RLHF / DPO：教"哪个答案更好"

SFT 教模型"照抄标准答案"，但它不区分好坏。RLHF 解决偏好对齐。

### 6.1 RLHF 三步

```
第 1 步：SFT，得到一个能正常对话的基础模型
第 2 步：人工对同一问题的多个回答排序 → 训练一个 reward model（打分器）
第 3 步：用 PPO 强化学习，让模型生成"打分高"的回答
```

### 6.2 DPO

省掉 reward model：直接用"好答案 / 坏答案"的配对数据，一步优化到位。

| 方法 | 需要什么 | 难度 | 现状 |
|---|---|---|---|
| RLHF (PPO) | 偏好数据 + reward model + PPO | 高，极难调稳 | 大厂用 |
| DPO | 只要偏好配对数据 | 中 | 开源社区主流 |

**这个阶段不需要动手做 RLHF/DPO**，能讲清"SFT 管格式、RLHF 管偏好"即可。

## 七、四种方法怎么选

| 方法 | 7B 模型显存需求 | 适用场景 |
|---|---|---|
| 全参微调 | 80 GB+ | 有 A100 集群、需要改模型核心能力 |
| LoRA | ≈ 18 GB | 单卡 24G（3090/4090），主流选择 |
| QLoRA | ≈ 8~10 GB | 单卡 16G（T4/4060Ti），个人开发者标配 |
| Prompt / RAG | 0 | **能解决就别微调** |

最后一条最重要：**90% 的业务需求用 prompt + RAG 就能解决**。上微调通常是为了格式稳定性、语气风格统一，或者把大模型能力蒸馏进小模型降成本。

## 八、对照自己的 Kaggle notebook

| notebook 里的写法 | 对应原理 |
|---|---|
| `labels = [-100] * n_prompt + ...` | 只对回答算 loss |
| `torch_dtype=torch.float16` | T4（算力 7.5）不支持 bf16，只能用 fp16 |
| `r=8, lora_alpha=16` | alpha = 2r，小数据集用小 r |
| `target_modules=[q/k/v/o, gate/up/down]` | 挂满注意力和 FFN，主流做法 |
| `per_device_batch=2, grad_accum=2` | 有效 batch = 4，显存不够时用梯度累积凑 |
| `model.disable_adapter()` | 关掉旁路，得到微调前的原始输出，用于对比 |
| `merge_and_unload()` | 合并后推理零开销，用于上线 |

## 九、面试题库（背这几条就够）

**Q1：LoRA 为什么能省显存？**
> 微调的权重增量是低秩的，用 B(d×r)、A(r×k) 两个小矩阵近似 ΔW。可训练参数从 d×k 降到 r×(d+k)，连带梯度和优化器状态一起省掉，训练显存降到权重的 1.5 倍左右。

**Q2：r 怎么选？**
> 数据少、任务简单用 8，通用场景 16~64。r 越大容量越大越容易过拟合。alpha 一般取 2r。

**Q3：为什么要屏蔽 prompt 的 loss？**
> SFT 建模的是条件生成分布，提问是条件不是目标。屏蔽后梯度只来自回答部分，避免模型学会复述问题。

**Q4：LoRA 和 QLoRA 的区别？**
> LoRA 只压缩可训练参数；QLoRA 额外把冻结基座量化到 4bit，显存需求再降 3~4 倍，代价是反量化开销和少量精度损失。

**Q5：微调能让模型学会新知识吗？**
> 很难。SFT 主要改变输出分布和风格，少量领域术语可以学到，成体系知识要靠继续预训练或 RAG。

**Q6：SFT 和 RLHF 区别？**
> SFT 用标准答案教"怎么答"；RLHF 用人类偏好排序教"哪个答得更好"。前者管格式和分布，后者管价值观和偏好对齐。

**Q7：LoRA 微调后怎么上线？**
> 用 merge_and_unload 把旁路合并进原权重，导出成普通模型，推理零额外开销；再转 GGUF 交给 Ollama/llama.cpp，或用 vLLM 部署成 API。
